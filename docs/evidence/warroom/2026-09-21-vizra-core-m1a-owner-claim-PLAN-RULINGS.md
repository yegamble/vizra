## Adopted as written (blocking before code unless marked)

- **S-1** `ip_prefix` writer is TOTAL: validates its own output against the frozen 0003 grammar (regex compiled from the migration file's bytes in the test), returns NULL for loopback, unspecified, zoned, unparseable and zero addresses; Go-side validation immediately before the INSERT; no SAVEPOINT around the audit insert. Tests: writer table test + `TestOwnerClaimSucceedsFromIPv6Loopback`.
- **S-4 / B-R9** the unclaimed guard is STRUCTURAL: one server-wide middleware, explicit allowlist (four probes + the two setup operations; sign-in joins in M1-B), everything else 403 including the router's 404 path; claimed bit cached permanently once true (monotonic), bounded cache while false; lookup error → 503, never 403, never allow. Route-walk test over `Server.Routes()`: every route is allowlisted or guarded, and the mutation is "add a route without a decision".
- **S-5 / B-6** a 429 writes NO audit row; rate-limit rejections are a metric; at most one `rate_limited` audit row per bucket per window, on the transition.
- **S-7** limit FAILURES, not attempts: cheap validation → digest compare → only a rejected attempt consumes budget; a request with the valid token is never answered 429 by the failure limiter; a separate, much higher hard ceiling protects the pool (state its value and that a flood past it is a network-level DoS). When a forwarded header is present and no trusted-proxy configuration exists, `ip_prefix` is NULL and the per-origin bucket is not used — never write the proxy's private prefix as if it were the client. Limiter fail-open on cache outage stays, with degraded readiness (ADR-003).
- **S-6b/c** the email-fold rule and the password rule are written INTO the migration header: folding is PostgreSQL's `lower()` on write and on every lookup, never Go-side; passwords are hashed as raw UTF-8 bytes with no Unicode normalisation; server-side BYTE bound on the password (≤ 1024 octets) as well as the character bound. Add both to the plan's hand-off list for M1-B.
- **B-R1 / B-R2** `username_fold` and `email_fold` are `GENERATED ALWAYS AS (lower(…)) STORED`; `users_email_fold_key` is partial (`WHERE email_fold IS NOT NULL`); `users_username_fold_key` is not. Preflight: sqlc 1.31.1 must not emit generated columns in an INSERT list — verify before writing the queries; an absent sqlc is BLOCKED for that lane.
- **B-3 / S-11** no input the OpenAPI schema accepts may produce a 5xx: validate in Go with the SAME literals the DDL enforces (test reads the migration bytes), express bounds in bytes, 23514 → 400 as a backstop with its own test; malformed fields never consume the token.
- **B-4** `BeginTx(ReadCommitted)` explicitly; no retry; the race test runs under server defaults `read committed`, `repeatable read` and `serializable`; mutation: drop the explicit option.
- **B-R4 / S-9** complete error-mapping table with a unit test over synthetic `*pgconn.PgError` values; the index name is read from the live database and pinned (the plan's DDL says `users_one_owner`, its transcript `users_one_owner_idx` — one is wrong); an integration test forces `users_one_owner` to fire through the handler (owner inserted out of band, then a valid token) → 409, no 5xx, no orphan credential, token unconsumed.
- **B-R5** trim → lowercase → shape → constant-time compare; a malformed token gets the SAME 403 and message as a wrong one. "No token row" is a fifth indistinguishable cause (S-12c).
- **S-8** explicit request posture: `Content-Type` exactly `application/json` (415), strict `json.Decoder` with `DisallowUnknownFields` (no `c.Bind`), `http.MaxBytesReader` (chunked bodies included), empty body → 400 before any database read; `Origin` when present must equal `VIZRA_PUBLIC_ORIGIN`, `Sec-Fetch-Site` when present must be `same-origin` or `none`, absence of both allowed; a mismatched Origin → 403 with a DISTINCT code so a misconfigured origin is diagnosable; `vizra doctor` compares the configured public origin with reality where it can.
- **S-10** the hasher is an injectable dependency with a call counter: ZERO derivations on every non-201 path (MUT-13: hash before the token check → red); the concurrency semaphore lives in a shared package M1-B will import, waiters honour the request context and fail 503.
- **S-12** `vizra claim-token` refuses, non-zero, when ANY user exists.
- **B-R3** `user_role` is a native enum (ADR-003: "ordered enum"; widening needs its own migration with `-- no-down:`); `credential_kind` is `text + CHECK` in house style. Correct the plan's statement about migrate-lint: widening a CHECK is ANNOTATED (`-- allow-destructive:`), not refused.
- **B-R7 / S-13** advisory-lock key is a registered constant with a registry comment; no `hashtext()`.
- **S-14** `TestUserRoleEnumOrderMatchesAuthzRanking` lands now — the enum order freezes here; `anonymous` is absent from the enum by intent.
- **B-2.1** drop `owner_claim_tokens.consumed_by` and its pair CHECK; the `succeeded` audit row ties generation to owner.
- **B-R8 / S-F8** acceptance evidence is taken on PostgreSQL 18 (CI pins it by digest); the 17.11 transcript is design validation and is labelled so. No PG-18-only `uuidv7()` — ids stay `uuid.NewV7()` in Go; never order by `(created_at, id)` across the two clocks.
- **B-R10 / B-R11 / B-R12** `/api/v1` is registered as a group and the probes stay unprefixed, stated in the plan; explicit casts in the claim CTE, `sqlc generate` preflighted on the real query; one explicit transaction (ClaimOwner → audit insert → commit), the "implicit transaction" sentence goes.
- **S-15 + the backend seat's table** every listed invariant gets a named test and a mutation that turns it red, or is recorded beside MUT-4 as review-only. Tests #12 and #18 state their mechanism so they cannot decay into skips.
- Token TTL: the builder proposes a short default for a token minted on demand (the security seat asked for shorter, without a number) and justifies it.
