### F-1: MAJOR. One of the three uploaded paths is never read by the gate; a capture API writes a PNG there and it is uploaded with the gate green

- **Rules:** R6 (the upload fires on red; the gate must hold for everything it publishes), R1, R14.
- **Changed side:**

  - `redact-artifacts.sh:215` and AGENTS.md:830, :846. These claim the gate "holds … for a spec's own capture API, for the files those write".
  - AGENTS.md:947-948 says the gate "refuses each of them once it lands under an uploaded path".
  - AGENTS.md:843 and :965-966 say that a file outside the scanned set "is not uploaded either".
- **Dependent side:**
  - `.github/workflows/e2e.yml:246` and `.github/e2e-pinned-steps.yml:138` upload `playwright-browsers.txt`.
  - AGENTS.md:777 says that file is "nothing sensitive".
  - `e2e-pinned-steps.yml:110-111` says it is safe because "the step that writes it is pinned and no other step may name it". But a spec in the lane step can write it. It is at the repository root, which is the Playwright process's working directory.
- **Reproducer:** a scratch spec in the clone. One test passes after `await page.screenshot({ path: "playwright-browsers.txt", type: "png" })`, and an unrelated test fails, so the run is red and the upload would fire. The run uses the lane's own `playwright.config.ts` with `E2E_BASE_URL` pointed at the synthetic page.


The same file can carry anything else a spec writes, such as page text or an unredacted signed URL, so the URL redaction and the `# Page snapshot` gate also never see it. That part predates this PR. What this PR adds is a claim that is false for this path.
- **Before this PR:** on `main` the gate never read the file either, but no pixel claim covered it. The pixel claim is new here.
- **Smallest fix:** remove `playwright-browsers.txt` from the upload, in `e2e.yml:246`, `e2e-pinned-steps.yml:138`, the allowlist at `check-e2e-lane.mjs:444/:1169` and AGENTS.md:777. Alternatively, move the record step to write into a gated directory after the lane, or have the gate validate the file (a regular file, not a link, printable ASCII, a bounded size).

### F-2: MAJOR. Playwright's HAR recorder, turned on by one declarative `test.use` line, publishes the page's image bytes with both controls green (and `recordVideo` passes the early control)

  - AGENTS.md:846 claims "it holds for a recorder turned on by any spelling".

- **Dependent side:** Playwright 1.63.0 `node_modules/playwright/lib/index.js:343-346` returns `{ ...contextOptions, ...options }`, and `:390` calls `browser.newContext({ ...videoOptions, ...options })`. A `contextOptions.recordHar` or `recordVideo` therefore reaches the context whatever `video` resolves to. Nothing in `e2e/`, `scripts/` or the lint config mentions `recordHar`, `recordVideo` or `contextOptions` (grep: 0 hits).
- **Reproducer:** a scratch spec with `test.use({ contextOptions: { recordHar: { path: "test-results/zz-sentinel-har/net.har", content: "embed" } } })`. One test loads a page with `<img src="/p.png">` and passes; an unrelated test fails.

  4. Or, at minimum, strike "covers everything Playwright's recorders and capture APIs write" from AGENTS.md:830 and `redact-artifacts.sh:215`, and add "a HAR recorded with `content: \"embed\"`" to AGENTS.md:835.

### F-5: MINOR. R11: a load-bearing clause of the runtime check survives its unit suite

- **Rule:** R11.
- **Where:** `e2e/harness/recorders.ts:90`, `if (typeof key !== "string" || !known) return false;`.
- **Reproducer:** a controlled mutation in the scratch clone. Removing `|| !known` leaves `npx vitest run e2e/harness/recorders.test.ts` at **13/13 passed**. The mutant is not equivalent:

```
recorderProblems({screenshot:"off", video:"off", trace:{mode:"retain-on-failure", sources:false, screenshotz: undefined}})
head:    ["trace"]
mutant:  []
```

With `screenshots` absent, Playwright falls back to its default and records screencast frames. That was the pre-PR value, which the PR measured at 3 and 2 frames. The gate would still catch the frames (`.jpeg` names or JPEG magic), so only the early control is affected.

Other mutants for comparison:
  - Killed: removing the Proxy, prototype, key-count or enumerable checks, or the primitive `===`.
  - Surviving but equivalent: removing the `"value" in descriptor` check (a getter's `descriptor.value` is `undefined` and fails the `===`), and removing the symbol-key check (a symbol key is not `known`).
- **Fix:** add a case with an unknown key whose value is `undefined`, and a missing required key, for example `{ mode: "retain-on-failure", sources: false, screenshotz: undefined }`.
