# Sentinel rules: what this codebase has actually got wrong

Every sentinel agent (`.claude/agents/sentinel/`) applies these rules. They are Vizra's equivalent of Greptile's learned rules. Each one came from a real defect that an independent verifier or a security seat found in this project, so each is a class to hunt for, not a style preference.

The chair adds a rule when a confirmed finding reveals a new class, citing the evidence. A rule is retired only by an explicit chair ruling.

| # | Rule | Hunt for | Origin (evidence) |
|---|---|---|---|
| R1 | **No false guarantees.** A sentence in docs, comments, the ledger or a PR body must claim no more than the control it describes. | "every", "never", "cannot", "all", "guarantees", "is refused" near a check. Mutate the check and see whether the sentence still holds. | Held repeatedly on 2026-09-23: core #8 R5-N1/R6-N1, meta #4 F-1, search #5 F16/F17, user #9 retention |
| R2 | **Do not identify a CI step by substring.** Guards must pin the whole step (byte-equal body, restricted keys), and strictness is never selected by the environment. | `includes(`, `contains`, `grep -q` over workflow text; env-driven `CI`/`FLOOR` switches | core #9, user #8 (`docs/evidence/warroom/2026-09-2*-*-VERIFY.md`) |
| R3 | **Allowlist an attacker-editable language; do not denylist it.** A guard that parses Makefiles, workflows, configs or specs must accept only a small grammar. | Guards that enumerate "bad" spellings; each new spelling is a bypass | core #10/#11, search #5 (eight rounds), `2026-09-23-vizra-search-pr5-closing-VERIFY.md` |
| R4 | **One reader per artifact.** Two readers of the same bytes must not disagree on where lines, records or fields begin. | A second `split("\n")`, `read_text()`, regex `re.M` or `splitlines` on the same file | search #5 F14 (continued comment) |
| R5 | **Fail closed on the unreadable.** A check that cannot parse, finds zero matches, or sees an empty set must fail, not pass. | "0 recipe lines … passed", empty-database passes, missing file treated as clean | core #11 R1-1 (database scan fail-open) |
| R6 | **A failure signal must not be the publishing trigger.** Detection that fails a test must also withhold whatever a failure uploads. | `if: failure()` uploads fed by guards that only fail tests | user PR B F1 |
| R7 | **Guard the effective value, not the call argument.** Screen the merged or effective options, config or environment the runtime actually uses. | Screens over function arguments where defaults are merged later (`_defaultLaunchOptions`, env layering) | user PR B R4-1 |
| R8 | **TTLs and windows: set at the start, never refreshed on use,** unless the doc says sliding. | `INCR` + `EXPIRE` on every call; cache timestamps updated on read | core #8 R4-A (owner-claim lockout) |
| R9 | **A cancelled context is not a backend failure.** Do not flip health, degraded or breaker state, or charge budgets, on `ctx.Err()`. | Error branches that do not check `ctx.Err()` first | core #12 L-2 |
| R10 | **Redact at the sink.** Every log, error or response value that can carry request data, DSNs, signed URLs or tokens goes through the redactor. The default logger redacts nothing. | `err.Error()` or request fields passed straight to `slog`, `fmt`, `log` | core #12 N-7/F-1 |
| R11 | **Tests must be able to fail.** Vacuous assertions, zero-selected `-run` patterns, floors a deleted file still passes, skipped required tests. | `-run` regexes; floor files; `t.Skip`; assertions on constants | core #8 NEW-B, core #9 check 5 |
| R12 | **Tests clean up after themselves.** Temp dirs, containers, volumes and goroutines. | `os.MkdirTemp` without `t.TempDir`/`t.Cleanup`; `docker run` without `--rm` | core B3 builder: 168 leaked 74 MB dirs caused ENOSPC |
| R13 | **Names are one per concept across repos.** One env or config name and vocabulary, everywhere. | The same key with different meanings (`VIZRA_SEARCH_MODE`), near-duplicate names | chair ruling 2h (2026-09-21) |
| R14 | **Public-repo exposure.** Since 2026-09-23 every artifact, job log and comment is public. | Uploads of traces, screenshots or HAR; logs echoing input; local paths in evidence | user #9, user #10, PR B review |
| R15 | **Supply chain and pins.** Actions pinned by SHA, images by digest, vendored contracts by recorded SHA with a check that the pin matches. | `@v4`-style action refs; `:latest`; vendored files without a source SHA check | meta `check-action-pins.py`, search #3 |
| R16 | **An upsert must not resurrect a terminal state.** `ON CONFLICT DO UPDATE` needs a `WHERE` that refuses consumed, revoked or deleted rows; a check made in an earlier snapshot does not survive a lock wait. | `ON CONFLICT … DO UPDATE` without a `WHERE`; `NOT EXISTS` guards read before a row lock | sentinel S-0002 (core owner-claim remint) |
| R17 | **An input validator must match the database constraint exactly,** and the test that says so must compare every constrained column. | Go `regexp` or `unicode` classes against PostgreSQL `[:space:]`/`CHECK`; a "never reached" fallback branch | sentinel S-0003 |
| R18 | **Wrap errors with `%w`, not `%v`,** where a caller branches on `errors.Is`/`As` (cancellation, not-found). | `fmt.Errorf("…: %v", err)` feeding `errors.Is(err, context.Canceled)` | sentinel S-0005 |
| R19 | **A probe must check WHO answered and WHAT they said,** not only the status code. A shared or default port can let another process answer for the one being probed. | Probes accepting any 2xx; shared default listen addresses across processes | sentinel S-0011 (worker healthcheck) |
| R20 | **Health state must recover on its own.** A degraded flag set by a failure must clear by its own recovery check, not wait for unrelated traffic to exercise the path. | Flags cleared only as a side effect of the next request on one route | sentinel S-0012 |
| R21 | **Test the documented artifact unmodified.** A test of a template, quick start or example that edits it before checking proves nothing about what the reader copies. | Tests that substitute values into `.env.example`, README commands or samples before running them | sentinel S-0013 |

| R22 | **A schema change must be safe for the previous binary (N-1).** An added constraint, NOT NULL or CHECK breaks an old writer during a rolling deploy; `NOT VALID` only skips the check at migration time, not for later UPDATEs. | New CHECK/NOT NULL on a table the old binary writes; "existing rows are not re-checked" claims | sentinel-pr S core #14 F-1/F-3 |
| R23 | **When code is rewritten, the mutations that test it must be retargeted.** A mutation whose pattern no longer matches is silently dead, not passing. | Text-pattern mutation harnesses (`demonstrate.sh`, `mutate.sh`) after refactors; harness-fail counts rising | sentinel-pr core #14 F-2 |

Two principles apply to every sentinel. **Confirm by execution:** a finding needs a reproducer that was run. **Stay inert:** no exploit payloads, and a safety-classifier stop is recorded and never routed around.
