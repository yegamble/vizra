### Q-001 — DECIDED 2026-09-15 (modified)
Decision text (replaces the proposal): "`vizra-search` is created in M0 as a real minimal service, not a placeholder: `/healthz`, `/readyz`, `/version`, and HMAC-verified `/internal/v1/search|suggestions|events` that return an explicit `not_indexed` status which core treats as fallback; it reports no `search_schema_version` until it owns migrations. Corrections: the proposal's "M2" was wrong (MILESTONES puts VZ-SEARCH-001/003/004 in M3, VZ-SEARCH-002 in M5); "mandatory by M4" is replaced by "managed default from M3".

### Q-028 — DECIDED 2026-09-15 (method); numbers PROVISIONAL until M0 measurement
"The cited evidence (RELEASE_ACCEPTANCE.md) prescribes dimensions, not numbers; the numbers below are provisional targets calibrated once by the first M0 boot-lane run on the reference host, after which VZ-OPS-007's rule applies (a budget may not be changed to excuse a failed run). Reference host = minimum supported host: 2 vCPU / 4 GB, Ubuntu 24.04 amd64, core profile with ClickHouse/IPFS OFF, images pulled (never built on the host), a 2 GB swapfile declared, worker concurrency 1, capped libvips operation cache, cache `maxmemory` set; `doctor` refuses hosts below the minimum by name and the installer docs ship a sizing table for larger tiers.
